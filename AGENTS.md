# AGENTS.md — portafolio

## Project

Professional portfolio website for Adilson Vargas Añez.

- **Primary narrative**: Data Engineering
- **Secondary line**: Data Analytics
- **Technical base**: Software Engineering (the site is built and maintained with engineering rigor)

## Governance

- `specs/constitution.md` is the source of truth for product decisions, scope boundaries, language, and the quality bar. Read it before planning or implementing.
- Changes follow the SDD pipeline: proposal → spec → design → tasks → apply → verify → archive. SDD artifacts live in Engram under topic keys `sdd/{change}/{artifact}`; `sdd-init/portafolio` holds project context.
- Never implement features that are not defined in an approved specification (constitution §10).
- Every feature is verified against its specification before it is considered complete (constitution §10).

## Tech Stack

- React + TypeScript + Vite + Tailwind CSS
- Deploy: Vercel — automatic from GitHub; preview per PR, production from the main branch
- Testing: Vitest (unit + component); business logic, helpers, and the data layer require coverage

## Architecture

- Component-based architecture.
- Content is separated from presentation: projects, skills, and experience live in typed, data-driven structures — never hardcoded in components (constitution §4).

## Quality Bar

- Type-safe
- Maintainable: code a third party can review
- Accessible: WCAG 2.1 AA
- SEO friendly
- Performance: LCP < 2.5s in production
- CI baseline: typecheck + tests + build on every PR

## Content

- The site is bilingual (ES/EN). Every published section must exist in both languages; do not publish a partially translated section (constitution §5).
- All professional information must be backed by the current CV and real projects.
- Each published project includes: problem/objective, data and context, real stack and tools, the author's role, measurable outcome, and repo/demo links (constitution §6).
- The official CV lives outside git; the repository is not its source of truth.

## Scope Boundaries (v1 no-goals)

Out of scope for v1: blog, CMS, authentication/login, e-commerce, multi-theme, complex SSR/ISR (constitution §9).

## Repo Facts

- Currently pre-scaffold: no package manifest yet. Existing: `specs/constitution.md`, `.atl/skill-registry.md` (generated by SDD init), `.gitignore`.
- The CV PDF is intentionally untracked-capable; asset strategy pending.
- Commit style: conventional commits. Never add AI attribution (no `Co-Authored-By`).

## Language

- Generated artifacts (code, comments, docs, specs, UI copy, tests, commit messages) default to English unless explicitly requested otherwise; Spanish artifacts use neutral/professional Spanish.
- The user's conversation language does not change the artifact language by itself.
